## Native infrastructure: protect the differences that matter

FluffySim's phase initialization separates one-time map state from phase layer holds. P2 clears slots0–53 then shows0x17; P3 clears, hides0x17 with0x00080004, shows0x28/0x29 and drives0x28 with0x00200010; P4 clears and shows0x28/0x29. Its phase-specific weather is35/106/105. Asu P3/P4 use map override dictionaries and P5 schedules a ShowOnly pass one second later. These are different engine contracts. The latter's one-second delay is not proof of native readiness and must not replace FluffySim's generation/readiness lifecycle.

The existing replay record in `FRU-ROADMAP.md` reports0x17 hide and0x28/0x29 show at950.097;0x28 state16/timeline32 plus weather106 at958.374. This is observed map/weather input, not proof of active rendered layers or collision. Preserve the established rendering and cold-load tests. P4 Fragment of Fate map-state differences need a real P4 snapshot before adding an entire map override.

Asu-specific candidates with concrete source provenance:

* `b789b4770cc4cb868b5d689e8a99e9f954432afa` modifies `SimCast` to defer casts/action effects while the native helper is pending and adds Ifrit/Titan tests. Its stated invisible-omen problem is relevant, but those tests concern UWU. FluffySim already has native pending-delivery tests and per-object readiness behavior; compare cancellation, deadline and dispatch ordering before adapting. A blanket extra delay would damage measured snapshots. This report does not claim the fix was adopted.
* `d6ad439b9c9b` uses engine NPC spawning for DSR knight models. FluffySim already has substantial actor visibility/initialization work and authenticated native knight behavior. An engine spawn path is not sufficient evidence to replace it, particularly offline.
* `88abe11da951` selects DSR P2 weather45; FluffySim already uses45. `1c7ad058f438` selects Thordan music921; FluffySim uses `PhaseMusic.Heroes`. This is convergence rather than a new feature to import.
* `5971dac9ee1c` addresses zones declaring no entrance barrier. FluffySim FRU/DSR explicitly declare native barriers; importing a no-barrier special case would be inappropriate without reproducing a local defect.
* `3fce7180eb2e` narrows DSR Spiral/Heavy omen duration and changes middle-tower priority. Native omen visibility deserves capture comparison; the tower priority is NAUR strategy and must not replace Elemental.

No independently demonstrated Asu-only accuracy correction for the nine custom scenarios was established by this audit. Consequently **no existing measured timeline or arena was replaced**. This is an explicit retain decision, not a claim that every local constant is perfect. Subsequent native dispatch or new-scenario changes must record their actual adoption and validation separately.

## Follow-up: narrowly adapted pending-helper cast delivery

The current FluffySim `SimCast.NativeCast` forwarded immediately to `BattleCharaProxy.ReceiveActorCast`; that method returns silently when its native pointer is null. `SimNpc.BeginPacketSpawn` explicitly permits an empty reserved slot for up to20 frames. Consequently a helper casting in its spawn tick loses its native bar/omen even though the logical action still resolves. Existing delayed-entry tests normally spawn actors before the attack and do not eliminate this gap.

Adapted the pending **cast** portion of Asu commit `b789b4770cc4cb868b5d689e8a99e9f954432afa` into `Core/SimObjects/SimCast.cs`. Delivery waits until packet spawn is validated; elapsed logical time is removed from both cast duration and omen delay. Damage scheduling is unchanged. Cancellation, action-effect release, expiration and Despawn suppress stale casts. Tests in `tests/AnoMech.Tests/Core/SimObjects/SimCastTests.cs` cover delayed native arrival and those terminal conditions. Build/test outcome is recorded in the mission validation report, not assumed here.

The Asu pending ActionEffect queue was deliberately **not** imported. FluffySim's `EnemyActionHandler` uses the returned native effect sequence for target EffectResult delivery; returning0 and sending the effect later does not preserve that linkage. Supporting delayed effects requires a separate sequencing design, not a cosmetic queue. Pre-spawning verified helpers remains the safe way to guarantee native releases for that case. Native-client rendering still requires the [playtest checklist](fru-native-playtest.md).
